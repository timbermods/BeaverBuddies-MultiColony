# Doc

Working notes kept with the source. Nothing here ships in the mod; the player-facing guides are at the repository
root (README.md, TWO-COLONIES.md, ALPHA-TEST-SCRIPTS.md, CONNECTION-PANEL.md, STEAM-INVITES.md, PLAYER-ACTIVITY.md)
and every change is in STABILITY-CHANGELOG.md.

## Written for this fork

| File | What it is |
|---|---|
| `Changelog.txt` | Where the changelog lives now (it was the original project's 1.5.0 draft). |
| `WorkshopDescription.txt` | The Steam Workshop page text in Steam's BBCode, from WORKSHOP.md. |
| `ToTestV6.md` | What in-game testing is owed, and where the scripts are (it was the original's to-do list for a game update). |
| `Consent.txt` | The plain text of the data-sharing consent dialog; the text the game shows is the `BeaverBuddies.ClientDesynced.ConsentMessage` line in `Localizations/enUS_BeaverBuddie.csv`. |
| `TranslationPrompt.txt` | A prompt for translating the mod's strings, with the current state of translations. |

## From the original BeaverBuddies (kept as they were)

These were made by the original project while hunting desyncs, against a Timberborn of that time, and are kept
because the reasoning still applies. None is generated by anything in this repository; treat the lists as
historical, not as an inventory of Timberborn 1.1.2.4.

| File | What it is |
|---|---|
| `Movement.md` | How a beaver's movement is animated between ticks, and where the animation desyncs came from (the Stability Fork's animation fixes, and this fork's `Fixes/AnimationFixes.cs`, are the response). |
| `AllEvents.txt` | The game's event bus event types, listed once to find the ones that reach the simulation. |
| `ClassesWithRandom.txt` | Game classes that draw random numbers, each marked addressed, verified, partly addressed, to investigate or unaddressed. |
| `ClassesWithTimeTriggers.txt` | Game classes that act on real or game time. |
| `ClassesWithHashSets.txt` | Game classes holding a `HashSet` (order-dependent iteration is a desync risk; the note at its top explains why it was judged safe). |
| `DerivedClasses.txt` | Every `MonoBehaviour` subclass and which Unity messages (`Awake`, `Update`...) it implements: what runs per frame rather than per tick. |
| `ParallelSingletons.txt` | A log excerpt naming the singletons the game ticks in parallel (see `DeterminismService`). |
| `UIFragments.txt` | The game's entity panel fragments, listed to find the UI paths that issue commands (`Events/EntityUIEvents.cs` covers them). |

The current, checked equivalent of these lists is `RuntimeChecks`: it scans the game's real assemblies for every
member the mod hooks, for simulation-reachable methods that read a dev key, for the events that leave joining open,
and for the actions' scopes, and fails when the game changes under the mod.
