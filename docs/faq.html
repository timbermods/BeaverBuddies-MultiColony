About the mod

What is BeaverBuddies MultiColony?

It is a multiplayer co-op mod for Timberborn in which each player runs their own colony on one shared map: their own districts, beavers, stock, working hours and science. There are no borders, and colonies' roads meet only at trading posts, where they barter. It is built on the BeaverBuddies Stability Fork and on the original BeaverBuddies by thomaswp and contributors, and keeps everything they do, including ordinary shared-colony co-op (turn Separate colonies for new games off). It is a beta.

Can we play one shared colony, as in the Stability Fork?

Yes. With Separate colonies for new games off, a new game is one colony that every player builds together, and a shared save (made that way, or in the Stability Fork) loads the same way. None of the colony model runs then: no owners or road rule, no Trading Post (not even in dev mode), District Crossings holding the game's 30 of a good, no colony check, and nothing of this mod's in the save. A shared save stays shared unless the host ticks Allow founding colonies in a shared game, which lets a player found their own colony and splits the save for good.

What does apply is what MultiColony adds to co-op in general: its desync fixes, the performance pass, the start prompt, the speed boost, going to a player, your own chat color. Every player needs MultiColony: it and the Stability Fork cannot join each other's games.

How is it different from the original BeaverBuddies?
  • Steam friend invites on Valve's current networking API, with no port forwarding.
  • An in-game connection panel with players, ping, sync status, tick rate, chat and a speed boost.
  • Player activity: teammates' cursors, selection outlines and Viewing / Editing labels, with per-player cursor styling.
  • Fixes for a water desync that depended on frame rate, an animation crash, random-number, saving and demolition problems, and more.
  • Clearer failures: a mismatched build is refused before the save is sent, and failed connections and actions end with a plain-language reason.

The home page and the changelog have the details, including how well each fix is confirmed.

Is it free?

Yes. It is free and open source under the GNU General Public License v3.0, and the original authorship and license are preserved.

Where do I download it? Is it on the Steam Workshop?

This fork is distributed through GitHub Releases only. It is not on the Steam Workshop or mod.io; the pages you may find there belong to the original project.

Which version of Timberborn does it need?

It is built and tested against Timberborn 1.1.2.4. Every player must run the same game version, because the mod compares it when someone joins.

Which platforms are supported?

It has been tested on Windows with the Steam version of Timberborn. Steam invites need the Steam version. Other stores, macOS and Linux have not been tested by this fork.

Playing together

How many players can play?

Up to four colonies; more players join as helpers of the host's colony. The Stability Fork underneath was played with two players; the colony model has had three short playtests so far.

Does everyone need to own Timberborn and install the mod?

Yes. Every player needs their own copy of the game and the same mod download. Only the host needs the save: guests receive a copy of it when they join, stored under Online Games.

Do I need to forward ports or use Hamachi?

Not with a Steam invite. For a direct IP connection, the default port is 25565 and your router must forward it. A virtual LAN such as Hamachi also works and avoids port forwarding.

Can someone join after the game has started?

No. Nobody can join once the host unpauses (the game's first tick), or once the host has placed or marked anything while waiting paused: everyone is sent the save the host started from, and a running game cannot be handed to a newcomer. Save, host again, and invite them; the host waits, paused, until everyone is in (or start a new game with the waiting room, where everyone is in before the world is made) (the connection panel says Joining: open; if the host places or marks something meanwhile, the game asks whether to start now or keep waiting, and a guest's change while the host waits is refused).

Do we share a screen?

No. Every player has their own camera and interface, and in MultiColony their own colony: your screen shows your colony's goods, population and science. You see the other players' cursors and selections anywhere on the map, and you can ping it.

What happens if the game desyncs?

The game tells you. The host chooses Save and Rehost, and guests choose Reconnect (wait for Rehost): a direct IP guest redials the address it used, and a Steam guest joins the host's new lobby when Steam shows it, or else accepts a fresh invite. In a separate-colonies game, colony state is compared with the host's every tick, so a MultiColony desync is caught the tick it happens; the log says whether it was the game's random state or the colony check that differed (a difference in the check itself is a bug in the mod, and worth reporting with both logs). Keep backups of your saves. See Troubleshooting.

Compatibility

Can I play with someone using the original BeaverBuddies?

No. Every player must run the exact same build, so a mixed session is refused. MultiColony has its own mod id, but it changes the same parts of the game as the original and the Stability Fork, so only one of them may be enabled at a time: if another is, the main menu names it and MultiColony stays out of the way.

Can Folktails and Iron Teeth play together?

Yes, since beta20 (not played yet). The host turns on Mixed factions for new games in Mod Settings, with separate colonies, and needs every faction unlocked on their own computer. In the waiting room each player picks their faction with the game's own faction switcher; each colony then has its faction's buildings, beavers, bots and storage, and colonies of different factions trade the goods both factions use, and science, but not beavers. A mixed save needs MultiColony: the plain game or the Stability Fork would load only one faction and drop the other's buildings and beavers. See TWO-COLONIES.md.

Can I use other mods?

Yes, but every player should have the same mods at the same versions. When someone joins, both players are shown a warning if their mod lists differ, naming the mods that are on only one computer or at different versions. It is only a warning: mods that only change the interface are usually harmless, but a mod that changes the simulation will make the games drift apart. A guest without a mod whose actions the host sends (MixedStorage, for example) leaves the game at the first such action, with a message naming the mod, and the host and the other players play on. Settings that affect the simulation (for example Reduce the number of forced pauses) are not compared and should match too. See Troubleshooting.

Do I need Harmony and Mod Settings?

Yes, both. Get them from the install guide.

Why do we all have to use exactly the same download?

The game must play out identically on every computer, and even a rebuilt copy of the same version can differ. So when someone joins, the mod compares the game version, its own version and its own files, and refuses any difference before the save is sent.

I installed an earlier download. What do I do about the old folder?

Replace your BeaverBuddies-MultiColony folder with the new one. If Documents\Timberborn\Mods still has a BeaverBuddies-Stability-Fork or BeaverBuddies-StabilityPreview folder (the Stability Fork, or an early two-colony build), delete it: only one BeaverBuddies can run at a time, and the main menu names any other that is enabled.

Privacy and safety

Does a Steam connection reveal my IP address?

Connections go directly between players when Steam can find a route and are otherwise relayed through Steam's network. Valve documents that relaying keeps players' IP addresses hidden from each other. With a direct IP connection, the host's address is shared with the players you give it to.

Can a stranger join my game?

Not over Steam. The host opens a friends-only lobby and only accepts players who joined it, so someone who knows your Steam ID cannot connect, and a Steam guest is seated by the Steam ID that Steam proves for its connection.

Direct IP is different. Whenever you host, even when you only invite friends over Steam, the host also listens on the direct IP port (25565 by default) until the game starts. Anyone who can reach that port (on your network, through a forwarded port, or over IPv6 if your firewall lets them in) can join, and the host cannot check who they are: someone who copies another player's id can take that player's colony. Forward the port, or let it through your firewall, only while you play by IP with people you trust.

What does the mod send about me?

Other players in your session receive your game actions and, if Player activity indicators is on, your cursor position, selection, recent building edits and the display name and color you chose. This fork's builds contain no bug-report upload token, so the Post Bug Report button does not upload anything, and diagnostic files are written only to your own computer.

How it works

How does it keep everyone in sync?

Everyone starts from the same save. Every action is sent to the host, which decides the tick it happens on and sends it to everyone. Because the game is deterministic, the same save and the same actions on the same ticks play out identically on every computer. The home page explains it in a minute, and the original project's wiki goes deeper.

What is the "tick rate" in the connection panel?

How many simulation ticks per second the game is running right now, averaged over about three seconds. It is around 1.7 at normal speed, rises with game speed (about 11.7 at the fastest button), and drops to 0 when paused.

To go past the fastest button, use the speed boost at the top of the chat box: - and +, or a typed number, add a constant to the speed everyone picked, so the fastest button with +0.5 runs at 7.5x. It goes from -6.5 to +23, and the game never runs below 0.5x or above 30x. How fast the game really goes is still down to the slowest computer; the tick rate says what is achieved.

Does the mod slow the game down?

Normal play has little overhead, and the latest release does less work every tick and every frame. The one big exception is Always Use Detailed Logging, which records a lot of extra detail for diagnosing desyncs. Leave it off unless you are hunting a desync.

Is there a delay when I do something as a guest?

A little. A guest's action goes to the host, which schedules it on a tick and sends it back, so it appears a short moment after you click. The Stability Fork removed about half a tick of that delay (roughly 0.3 seconds at normal speed) by sending your actions immediately, and over Steam that delay no longer grows as the game speeds up.

The project

How do I update?

Download the new zip, close the game, and replace the BeaverBuddies-MultiColony folder (delete any BeaverBuddies-Stability-Fork or BeaverBuddies-StabilityPreview folder too if you still have one). Everyone updates together, because different builds will not join each other.

How do I report a bug?

Open an issue on the project's GitHub page and attach both players' Player.log. Collecting logs explains where to find them.

What are the known limits?
  • Everyone must run the exact same build. Other mods should match (you get a warning when they do not), and settings are not compared.
  • Nobody can join after the host unpauses, or after the host changes anything while waiting paused, or after a waiting room's Start Game.
  • Desyncs can still happen; a colony difference is caught the tick it happens.
  • Beta: the colony model has had three short playtests so far. Up to four colonies; tested on Windows with the Steam version only.
  • Text added by this mod is English only. Other languages show the English text for those strings.
  • The game ends only when every beaver on the map is gone, not per colony; the map (water, droughts, badwater) is shared.
  • The full list is in TWO-COLONIES.md.
Who made it?

The multiplayer design and most of the code come from the original BeaverBuddies by thomaswp and contributors. This fork is maintained by Timbermods. It is an unofficial community mod for Timberborn, not affiliated with or endorsed by Mechanistry.
