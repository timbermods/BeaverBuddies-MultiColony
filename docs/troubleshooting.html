Troubleshooting

Find your symptom and try the fixes in order. Still broken? Send every player's logs and we'll look.

Check these first

Most multiplayer problems come from a difference between the players. Before anything else, check that everyone has:

  • the exact same download of the mod (the mod list shows the version, and it must be the same zip, not just the same number),
  • the same version of Timberborn,
  • the same other mods enabled, at the same versions,
  • only one BeaverBuddies installed,
  • and has fully restarted the game since installing or updating.

Installing and loading

The mod doesn't load, or doesn't show in the mod list

Try this

  1. Check the folder. You should have Documents\Timberborn\Mods\TimberTogether\version-1.1\manifest.json. A common mistake is an extra nested folder after extracting the zip.
  2. Make sure Harmony and Mod Settings are installed and enabled. The mod needs both.
  3. Enable Timber Together in the mod manager and restart the game.
  4. The mod is built for Timberborn 1.1 (tested on 1.1.2.4). Older game versions won't run it.
  5. Open %USERPROFILE%\AppData\LocalLow\Mechanistry\Timberborn\Player.log and search for Timber Together v1.4.0-rc4 is loaded!. If it's there, the mod loaded and the problem is elsewhere.
There are two BeaverBuddies in the mod list, or the main menu names another one

Why

Only one BeaverBuddies can run at a time: Timber Together, the Workshop BeaverBuddies and the Stability Fork all change the same parts of the game. If another one is enabled, the main menu names it and Timber Together doesn't start. A second copy of Timber Together in your Mods folder, or a BeaverBuddies-Stability-Fork or BeaverBuddies-StabilityPreview folder, conflicts the same way.

Try this

Keep exactly one BeaverBuddies. Unsubscribe from the Workshop version, delete any extra copy and any BeaverBuddies-Stability-Fork or BeaverBuddies-StabilityPreview folder from Documents\Timberborn\Mods, then restart the game. Your saves aren't kept in the Mods folder.

After a Timberborn update, co-op stops at load with a message

The update changed a part of the game Timber Together corrects for co-op. Rather than let the game go out of step, co-op stops at load and the message names the part; single player carries on. Update Timber Together when a new build is out, all of you together.

Joining a game

Joining is refused: "Multiplayer build mismatch"

Why

When someone joins, the mod compares the game version, the mod version and the mod's own files (Buildings and TemplateCollections among them), before the save is sent. It refuses any difference, because two different builds can't stay in sync, and the message names what differs. A copy someone built themselves can be refused even when the version number matches, and an old version still running in memory is detected too.

Try this

  1. Have everyone install the same zip: the host's, or the one from the newest release.
  2. Replace the TimberTogether folder, then fully restart Timberborn on every computer.
  3. Compare the three readings with your host: mod version, game version, same zip.
A warning says my mods and the other player's mods aren't the same

Why

When someone joins, both players' games compare their lists of enabled mods and warn you if any mod is on only one computer or at a different version. The host sees the warning before starting; a guest sees it as soon as the game has loaded. It's only a warning, because the mod can't tell which mods matter. A mod that changes the simulation (a housing or pathfinding mod, for example) will make the two games drift apart, which is a desync. A mod that sends its own multiplayer actions or adds content the host uses (MixedStorage, for example) must be on every computer: a guest without it leaves the game with a message naming the mod, and the host and the other players play on.

Try this

  1. Read which mods are listed: "Only on your computer", "Only on …'s computer" and "Different versions".
  2. Make both lists identical: install and enable the same mods at the same versions on every computer, or turn the listed mods off on both. Mods that only change the interface are usually harmless.
  3. Restart Timberborn on the computers you changed, then host again.

The warning is also written to Player.log: search for "Mod lists differ".

Invite Friends does nothing, or my friend gets no invite

Try this

  1. Right after hosting starts, the Steam lobby is still being created. Wait a moment and click Invite Friends again. The Steam overlay should open.
  2. On the host, make sure Enable Steam Networking is on in Mod Settings (it is by default).
  3. Both players need to be online in Steam. The friend must be on your Steam friends list and own Timberborn on Steam.
  4. Your friend can also use Join co-op game on the main menu, which lists their Steam friends' co-op games.
  5. Both of you need the same build of the mod and the same game version.
  6. If Steam still won't connect, host with a direct IP or Hamachi instead. Steam problems never stop direct IP hosting.
The invite says the host has already started

Why

Nobody can join once the host presses Start Game on the Co-op Game page. An old invite explains that instead of hanging. A game that has started may also simply drop off the Join co-op game list.

Try this

The host chooses Save and Rehost in the game menu, and you choose Rejoin or wait in Join co-op game. Everyone meets on the Co-op Game page, and Start Game carries on.

A friend lost the connection

They choose Rejoin on the lost-connection message (or wait in Join co-op game), and the host chooses Save and Rehost in the game menu, in either order. The friend goes to the main menu and lands on the host's Co-op Game page as soon as it opens; when everyone is ready, Start Game carries on.

"… is waiting for you in a co-op waiting room"

You accepted an invite, or used Join, while you were in a game, and the host is on a Co-op Game page. Go back to the main menu, then accept the invite again or join from there.

My game failed to load after Start Game

Nobody can join a game that has started, so there's no way back into that one. The host uses Save and Rehost, and you join that. If it happens again, send every player's logs.

Joining over Steam takes forever or fails with a Steam message

Why

Steam connects players directly when it can find a route and relays through its own network otherwise. Failures end with an explanation that includes Steam's own reason, for example "The connection timed out. Steam could not find a working route between you." The same detail is written to Player.log.

Try this

  1. Read the message. It says what Steam reported.
  2. Make sure you're both on the exact same build. If joining sits on "Receiving map…" and never finishes, that's the first thing to rule out.
  3. Try again. If it repeats, use direct IP or Hamachi.
  4. If it keeps failing, collect every player's logs and ask for help.
Direct IP won't connect

Try this

  1. The host must already be hosting, and mustn't have started or changed anything yet.
  2. Use the right address: your public IP for the internet, or the virtual-network address (for example from Hamachi) if you use one.
  3. The default port is 25565. Your router must forward it to the host's computer, and your firewall must allow Timberborn.
  4. Port forwarding is the hard part. A virtual LAN such as Hamachi avoids it and has been tested. So does a Steam invite.

Colonies and trading

"That would join another colony's roads"

A path of yours would touch their road (finished or still being built), or a building's door would open onto or beside it. Keep your roads a cell apart from theirs, and away from their district center. To link the two colonies, put a Trading Post between them. Ctrl+L shows whose roads are whose.

A Trading Post says "Not trading yet"

Each half needs a different colony's road at its door: yours at one end, theirs at the other. It starts trading as soon as both roads reach it. If a round waits, the panel says why: paused or flooded, no workers, no room, or nothing left to bring.

Ctrl+K says this is one shared colony

The save is a shared game. To split it, a player other than the host opens the game menu (Esc) and chooses Found your own colony, or the host ticks Separate colonies on the save's Co-op Game page and hosts it again. Either makes it separate for good, and the colony you built together stays whole as the host's. Choose your start explains both.

Everything I do is refused right after joining

The host hasn't seated you in a colony yet; wait a moment. If it persists, send the logs. Later on, "That belongs to another colony" means just that: you can only change your own colony's buildings, beavers, districts, marks and settings.

While playing

The connection panel shows something other than "In sync"
StatusWhat it means and what to do
Catching upGuests only. Your game is three or more ticks behind the host. Brief spells are normal. If it keeps growing, your connection or computer can't keep up, so check your ping and try a lower game speed.
Waiting for hostGuests only. Your game has used everything the host sent and is waiting for more. A flash is normal. If it stays, check the connection.
Connection unstableSomeone has stopped responding for five seconds. Check their connection. If it doesn't recover, the session may end.
Out of syncA desync was detected. See the next item.
DisconnectedThe session has ended. Rejoin, or have the host rehost.

Ping colors: normal text is 80 ms or less, yellow up to 160 ms, red anything higher or no response. The dot beside the status is green when you're in sync, yellow while catching up or waiting for the host, and red when the connection is unstable, out of sync or disconnected.

A desync: "A connected player desynced and cannot continue playing"

Why

The players' games have drifted apart. Every copy of the game must make exactly the same decisions, and something made one of them differ. Known causes are removed, but none of that is a promise. The log says which check caught it: Random state mismatch (the game's random state at an action) or Colony state differs (the colony check, in a separate-colonies game; a difference there may be a bug in the check itself, so send every player's logs). An earlier Entity mismatch or Walker mismatch line, which doesn't stop the game by itself, says when the two games first differed.

Try this

  1. The host chooses Save and Rehost.
  2. Guests choose Reconnect (wait for Rehost), in any order: each goes to the main menu and lands on the host's Co-op Game page as soon as it opens. A direct IP guest redials the address it used, and a Steam guest joins the host's new lobby when Steam shows it (otherwise it accepts a fresh invite).
  3. Everyone presses Ready, and the host presses Start Game.
  4. You may need to restart the game if problems persist.

Things that cause it

  • Different mods, or different mod versions. The game warns you about this when someone joins (see the mod warning), so take that warning seriously.
  • Different settings that affect the simulation, for example Reduce the number of forced pauses. Keep them identical.
  • Dev mode's tools. Only its instant unlock, Finish now and Add 1000 Science are shared; its other tools and keys desync the game.

Keep backups of your saves. In a separate-colonies game every computer writes a report when a desync happens: send them all.

"Multiplayer has stopped because this action may have changed only part of the game state"

Why

A multiplayer action couldn't be completed on one player's game. Carrying on could leave two games different without anyone noticing, so the mod stops the session.

A guest can also see "An action from the host could not be read", ending "Nothing of that action was played here". The host sent an action, usually from a mod the guest doesn't have, which the message names. Nothing went wrong: that guest has left the game, and the host and the other players play on. Install the same mods on every computer (see the mod warning); the host then chooses Save and Rehost and the guest joins again. The steps below are for the other message.

Try this

  1. Press Escape to open the menu, return to the main menu and reload a known-good save before hosting again.
  2. Don't overwrite your good save with the session that stopped.
  3. If it repeats with the same action, collect the logs and say what you were doing.
The connection dropped and the game is paused

What happens

When a guest loses the host, the game says why and stays paused, and the menu and controls work again. Nothing more will be played in that session.

Try this

  1. Press Escape to open the menu. You can save from there.
  2. Return to the main menu and join again once the host has hosted again. Steam guests accept a fresh invite; direct IP guests reconnect.
The game is laggy or my FPS is low in multiplayer

Try this

  1. Turn off Always Use Detailed Logging in Mod Settings, on every computer. It records a lot of extra detail for diagnosing desyncs and noticeably slows the game. It's off by default.
  2. Look at the connection panel. A red ping or a high Behind host value means the connection is the problem, not the game.
  3. Try a lower game speed if a slower computer keeps falling behind, or, as the host, click Ease off below in the connection panel and pick a frame rate: the game then slows a little while a guest stays under it.
  4. More colonies mean more to simulate: prefer a smaller map. Ctrl+Shift+J writes a diagnostics report that shows where the time goes.

Panel, cursors and settings

The connection panel is missing

Try this

  • The panel only appears in multiplayer games.
  • Check Mod Settings, Timber Together, Connection panel. It may be set to Hidden.
  • If you bound the Toggle connection panel key, you may have hidden it with that key.
  • It may be collapsed to a single line (a colored dot, the player count and one ping). Click the line to expand it.
  • It may be in a different corner. See Connection panel position.
I can't see other players' cursors, labels or pings

Try this

  • Player activity indicators must be on in Mod Settings. A player who turns sharing off disappears from your view until they turn it back on.
  • A cursor is hidden while it's over the game's interface, outside the game window, or off the map. Yours is hidden while the game window isn't focused.
  • Open Options, Player cursors and check that you haven't made that player's cursor tiny (size 50% is the minimum) or nearly invisible (transparency goes up to 90%). Reset restores the defaults.
  • For pings, bind a key for Ping Location in the game's keybinding settings.

Collecting logs

Logs from every player, not just the one who saw the problem, are what make a problem diagnosable. Steam failures and desyncs record their details there.

  1. Close the game so the log is complete.
  2. Open %USERPROFILE%\AppData\LocalLow\Mechanistry\Timberborn in Explorer (paste it into the address bar).
  3. Copy Player.log. If the problem happened in an earlier session, also copy Player-prev.log, the log of the session before.
  4. Copy your newest report from the TimberTogether-Reports folder next to the logs. In a separate-colonies game every computer writes one by itself when a player desyncs; Ctrl+Shift+J writes one any time (it's also copied to your clipboard).
  5. If a desync happened with detailed logging on, the water diagnostics are saved in the TimberTogether-Diagnostics folder next to the logs. They're written only on your computer and never uploaded.
Before you share

Logs contain file paths, which include your Windows user name. Look through the file before you post it if that matters to you.

The Post Bug Report button in the desync dialog doesn't upload anything in Timber Together's builds, because they contain no upload token. Send the files by hand instead.

Leave Always Use Detailed Logging off unless you're asked to turn it on. It costs performance.

Getting help

Open an issue on the project's GitHub page (not the original BeaverBuddies project) and include:

  • what you were doing and what you expected,
  • the mod version, the game version, and whether you connected over Steam or direct IP,
  • every player's Player.log and newest TimberTogether-Reports report,
  • screenshots of anything on screen.

Also check the FAQ, which answers the common questions.
